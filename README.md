# マレーシア研修旅行アプリ — 設置手順

出発前の準備から、研修中の日程確認、帰国後の提出まで通して使うアプリです。
iPhoneのホーム画面アプリとして、オフラインでも動く状態にするまでの手順です。
PCがあればPCで、なければiPhoneのSafariだけでもできます。所要10分ほど。

---

## ファイル構成

以下6つをすべて同じ階層に置きます。

```
index.html              アプリ本体
sw.js                   オフライン動作用
version.json            更新確認用（端末はこれを見て新版を判断）
manifest.webmanifest    アプリ名・アイコンの定義
icon-180.png            ホーム画面アイコン（iOS用）
icon-192.png
icon-512.png
```

**index.html はこの名前のまま変えないこと。** 変えると sw.js と manifest が
参照している先とずれて、オフライン動作が壊れます。

---

## 1. リポジトリを作る

1. github.com にログイン → 右上の「+」→ **New repository**
2. Repository name に `malaysia-trip` などを入力
3. **Public** を選ぶ（Private だと GitHub Pages は有料プランが必要）
4. **Create repository**

## 2. ファイルをアップロードする

1. 作成直後の画面にある **uploading an existing file** をクリック
   （見当たらなければ Add file → Upload files）
2. 上記6ファイルをまとめてドラッグ、またはファイル選択で追加
3. 下の **Commit changes** を押す

## 3. GitHub Pages を有効にする

1. リポジトリの **Settings** タブ
2. 左メニューの **Pages**
3. Source を **Deploy from a branch** に
4. Branch を **main**、フォルダは **/ (root)** を選んで **Save**
5. 1〜3分待つと、ページ上部にURLが表示されます

```
https://<ユーザー名>.github.io/malaysia-trip/
```

## 4. iPhoneのホーム画面に追加する

1. **Safari** でそのURLを開く（Chromeなど他のブラウザではダメ）
2. 画面下の **共有ボタン**（□に↑）をタップ
3. 下にスクロールして **「ホーム画面に追加」**
4. 名前を確認して **追加**

これで完了です。ホーム画面のアイコンから、アドレスバーなしの全画面で起動します。

## 5. オフラインで使えるようにする

追加したら、**ホーム画面のアイコンからアプリを開き、
設定タブの「オフライン用に保存する」を押してください。**
ここでファイルが端末にコピーされます。

すでに保存済みの場合、このボタンは出てきません。

確認方法：機内モードにしてからアイコンをタップ。
中身が普通に表示され、画面下に「オフラインで動作中」と出れば成功です。

### 通信について

**このアプリは自分から通信しません。** 起動しても更新の確認はしません。
ネットにつなぐのは、設定タブの以下のボタンを押したときだけです。

- 「オフライン用に保存する」（最初の一度だけ）
- 「更新を確認する」（自分が確認したいとき）
- 最新情報タブの「最新の情報を取得」（為替・天気を取り寄せたいとき）

海外で従量制の回線を使っていても、勝手に通信量を消費することはありません。

---

## 内容を書き換えたくなったら

アプリ内の **編集ボタン** で項目の追加・修正・削除ができます。
ここでの変更は端末に保存されるだけなので、GitHub側の更新は不要です。
オフラインのままでもできます。

---

## アプリ本体を更新する（配布側の作業）

ファイルそのものを直したいときの手順です。**この作業だけはネットが必要**です。

### 1. ファイルを直す

GitHub上で該当ファイルを編集するか、直したファイルを上げ直します。

### 2. 3か所の番号を上げる

| ファイル | 場所 | いつ上げるか |
|---|---|---|
| `sw.js` | `var CACHE = "prep-v12";` | **毎回必ず**（v13, v14…） |
| `index.html` | `var APP_VERSION = "2.5";` | 毎回（表示用） |
| `index.html` | `var DEFAULT_REV = 1;` | やること／持ち物の項目を足したときだけ |
| `version.json` | `"version"` と `"cache"` | **毎回必ず**。index.html / sw.js と揃える |

`CACHE` を上げ忘れると古いキャッシュが残り、更新が誰にも届きません。
ここが一番のハマりどころです。

**3つの版番号は必ず揃えること。** `version.json` の `version` と
`index.html` の `APP_VERSION` がずれていると、端末が永遠に
「新しい版がある」と言い続けます。

### 3. 端末側で受け取る

GitHub Pages への反映に1〜2分。そのあと端末で
**設定タブ → 更新を確認する** を押します。新しい版があれば画面下にバナーが出るので、
「更新する」を押すと切り替わります。

**確認は自動では行われません。** 自分で押したときだけです。
押さなければ古い版のまま使い続けられるので、通信量を使いたくないときは
そのままで問題ありません。

---

## 更新してもデータは消えません

チェック、メモ、自分で追加・編集した項目は、アプリ本体とは別に保存されています。
更新しても、そのまま引き継がれます。

**`DEFAULT_REV` を上げた場合**は、設定タブに
「新しい項目を取り込む」ボタンが出ます。押すと、追加された項目だけが
リストの末尾に足されます。今あるチェックや自分で書いた項目は消えません。

---

## データはこの端末だけのもの

チェック、メモ、プロフィール、編集した項目、取得した為替・天気は
localStorage に、添付ファイルは IndexedDB に入ります。
どちらもこの端末のこのブラウザの中だけで、サーバーには一切送られません。GitHub Pages は
ファイルを配るだけで、データベースも受け口も持っていません。

同じURLを他の人に渡しても、相手のチェックがこちらに見えることも、
こちらのチェックが相手に見えることもありません。

## 使っている外部API

「最新の情報を取得」を押したときだけ、次の2つを呼びます。どちらも
APIキー不要・無料・CORS対応です。

| 用途 | エンドポイント |
|---|---|
| 為替 | `api.frankfurter.dev/v1/latest`（ECB基準レート） |
| 天気 | `api.open-meteo.com/v1/forecast`（選んだ地域） |
| 空気質 | `air-quality-api.open-meteo.com/v1/air-quality`（PM2.5・AQI） |

Service Worker は自オリジン以外のリクエストを横取りしないので、
これらは常に生のネットワークへ行きます。

## 注意

- Public リポジトリの中身は誰でも見られます。**パスポート番号、保険証券番号、
  クレジットカード情報などはアプリのメモ欄に書かないでください。**
  メモの内容自体は端末内にしか保存されませんが、事故を避けるため。
- チェック・メモ・編集内容は Safari のローカル保存領域に入ります。
  Safari の「履歴とWebサイトデータを消去」を実行すると消えます。
- 大事な項目は紙にも控えておくと安心です。
- **ホーム画面のアプリと Safari は別々のストレージを持ちます。**
  Safari で新しい版が見えていても、アプリ側は自動では変わりません。
  アプリ側で「更新を確認する」を押してください。
- どうしても入らないときは、設定タブの「アプリ本体を入れ直す」。
  Service Worker とキャッシュだけを捨てて取り直すので、
  チェック・メモ・プロフィール・添付ファイルは残ります。
- 更新の確認と適用にはインターネット接続が必要です。オフライン時は
  設定タブの「更新を確認する」を押しても何も起きません（そのまま使えます）。
- 「表 : 3か所の番号」の `sw.js` の `CACHE` を上げ忘れると、
  端末側でいくら「更新を確認する」を押しても新しい版は届きません。
